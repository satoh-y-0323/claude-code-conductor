## この文書群が何のためにあるか

C3 は場当たり的対応の積み上がりが実測で確認されており、**作り直しも射程に入れた棚卸し**を行っている。
本目次はその第一歩であり、次の 4 つの用途を同時に持つ。

1. **作り直すべきかの判断材料** — 全体像が無ければ「作り直す方が安いか」を判定できない
2. **「何を捨てるか」の決定の入力** — 死んだコード・読まれないデータ・重複の一覧
3. 作り直す場合の**受け入れ基準**
4. 作り直さない場合の**削除の安全網**

> **これは詳細設計書ではない。** 1 項目 1 行の目次であり、各項目には根拠の `file:line` が付く。
> 読み取れなかったものは「未確認」と明記してあり、**推測で埋めていない**。

### 旗の意味

| 旗 | 定義 |
|---|---|
| `[実体なし]` | ドキュメント・規約に書かれているが実装が存在しない／到達不能 |
| `[未文書化]` | 実装はあるがどのドキュメントにも記載が無い |
| `[未登録]` | hook ファイルが存在するが `settings*.json` に登録が無い |
| `[起動元なし]` | agent / skill の定義があるがどこからも起動されない |
| `[規範衝突]` | agent 定義の禁止事項と、実際に課される作業が矛盾する |
| `[重複]` | 他の skill / rules / docs と同内容が書かれている |
| `[書き手なし]` / `[読み手なし]` | 状態ファイル・テーブルに書く／読むコードが存在しない |
| `[手動のみ]` | 規約上必須の関所だが CI が自動実行していない |
| `[三重定義]` | `.gitignore` / `_excludes.py` / `hatch_build.py` の同期ルールに関わる重複 |
