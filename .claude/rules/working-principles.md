# 作業の進め方の原則

全 role が作業を進めるときに守る原則。判定・検証の規律は `judgment-principles.md` にある。

## 1. 事実の出所は 1 箇所にする

要件・設計・計画・プロンプトへ同じ事実を重複して書かず、出所の 1 箇所を決めて、他は参照で指す。

## 2. 作業ディレクトリから離れない

作業ディレクトリ（プロジェクトルート。worktree の中ではその root）から cd で離れない。別の場所のファイルは絶対パスで指す。C3 の一部の hook は作業ディレクトリを基準に書き込み先を判定する（例: `.claude/hooks/report_path_guard.py`）。worktree の後にプロジェクトルートへ戻す cd（`parallel-agents` の既知バグ対策）はこの規則に合う。親はサブエージェントへの指示にもこの規則を含める。

## 3. 後始末はユーザーに渡す前に自分で行う

親は、後始末の手順をユーザーに渡す前に、自分で、または担当エージェントに依頼して行えないかを確かめ、行えるならそうする。消す・書き換えるときは先に写しを取る。

親自身が直接行う範囲は広げない（自律では `autonomous-mode` SKILL.md「親の直接編集」の列挙の中、HITL では既存の関所の中。削除・公開・権限の設定はユーザーの許可を得る）。

## 4. 記録の時刻は実時刻を取得する

記録（gaps 台帳・セッションファイル）に書く時刻は推定せず、その場で実時刻を取得して書く。

## 5. git 管理外の記録は切り詰めてから書かない

git 管理外の記録ファイル（`.claude/reports/` の gaps 台帳など）を書き換えるとき、先に切り詰めない（一時ファイルに書いて置き換える）。消えると復元できない。

## 6. エージェントの推奨が文書の約束と食い違うとき

エージェントの推奨が文書の約束（README・docs など）と食い違うとき、親はそのまま流さず、現物の根拠を添えて推奨を出し直し、両方を並べてユーザーに示す。約束そのものを変えるべきかは `.claude/CLAUDE.md`「根本解決の原則」（契約も根本解決に従う）に従う。

## 7. background work が残ったサブエージェント

親は、終了通知に background work が残っていると出たサブエージェントを、報告を受け取った時点で止め、`git status --short` で残った変更を確かめる。
